# Pangasinan Heritage Digital Showcase

**Student:** Blessy Fernandez
**Selected Framework:** React with Next.js 14 (App Router)

Source code for Activity 1.1 (The Pangasinan Heritage Digital Showcase).
Built with **React / Next.js 14 (App Router) + TypeScript**, styled with
Tailwind CSS, and structured around Brad Frost's **Atomic Design**
methodology.

## Getting started

```bash
npm install
npm run dev
```

Open http://localhost:3000. `npm run build && npm run start` produces the
static production build (the whole site pre-renders to static HTML — no
server required, matching the JAMstack deployment requirement). Both
`npm run build` and `npm run lint` type-check the whole project.

## Project structure

```
app/                     Next.js App Router entry points
  layout.tsx              root layout, self-hosted fonts, metadata
  page.tsx                assembles the 3 sections (Hero, Heritage
                           Grid, About) from organisms only
  globals.css              Tailwind layers + a11y helpers (skip link,
                            focus rings)

components/
  atoms/                  Button, Typography (Eyebrow/Heading/Body),
                          Icon, HeritageImage
  molecules/              HeritageCard, NavItem, SearchForm
  organisms/              Header, Hero, HeritageGrid, HeritageModal,
                          AboutSection, Footer

lib/
  data/heritageSites.ts   content + the HeritageSite type for the 3
                          featured sites — edit this file to add/change
                          a site, no markup changes needed
  tokens/colors.ts        single source of truth for the color
                          palette; imported directly by
                          tailwind.config.ts

public/images/            hero photo + the 4 card/section photos (see
                          note below)
scripts/generate_images.py  no longer used for the featured sites (all
                          4 cards now use real photography) — kept for
                          reference in case a future site needs a
                          quick placeholder before a real photo is
                          sourced
tsconfig.json / next-env.d.ts  TypeScript project config (generated by
                          the Next.js TypeScript integration)
```

## Featured sites

Hundred Islands (Alaminos City), Bolinao Lighthouse, and Balungao Hot
Spring — content and types live in `lib/data/heritageSites.ts`.

## About the images

All five photos in `public/images/` are real photography: `hero-pangasinan.jpg`
(aerial view of the Hundred Islands with the Christ the Redeemer statue
on Governor's Island) as the Hero background, `card1.png`–`card3.png`
for the three Heritage Card thumbnails (Hundred Islands, Bolinao
Lighthouse, Balungao Hot Spring respectively), and `card4.png` as the
collage photo in the About section. None of them are the placeholder
illustrations `scripts/generate_images.py` can generate — that script
is kept only as a fallback for a future site added before real
photography is sourced for it.

## Notes on the requirements this build targets

- **Lightning fast**: fonts self-hosted via `@fontsource` (no
  Google Fonts round-trip), images served through `next/image` with
  responsive `sizes`, page is 100% statically pre-rendered.
- **Mobile-first**: every section is authored mobile-first with
  `sm:` / `lg:` breakpoints layered on top (see the "Responsive logic"
  comment in each organism/molecule file). Verified at 375px (mobile),
  768px (tablet) and 1440px (desktop).
- **Accessible**: skip-link, visible focus rings, semantic landmarks
  (`header`, `main`, `footer`), descriptive `alt` text, labelled
  mobile-menu button with `aria-expanded`/`aria-controls`.
- **Maintainable**: atomic component layers, full TypeScript types on
  every component's props, a single data file for site content
  (`lib/data/heritageSites.ts`) and a single token file for color
  (`lib/tokens/colors.ts`).
- **Deployable**: standard Next.js static export — deploys to any
  static/JAMstack host (Vercel, Netlify, GitHub Pages via `next
  export`-style hosting, etc.) with no custom server.
